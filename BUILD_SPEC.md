# AI Limits Monitor 2.0.3

## Назначение

Виджет для Windows и macOS показывает оставшиеся лимиты и историю использования Claude Code, Codex, Grok Build и Antigravity.

## Запуск приложения

- Единственная пользовательская точка входа: `monitor.py`.
- Виджет и встроенный сборщик работают в одном процессе. На чистой установке сборщик обращается к четырем настроенным источникам и передает данные окну внутри процесса. Обработчики --claude-statusline и --antigravity-statusline принимают только сведения о квотах через стандартный ввод.
- При запуске открывается компактный монитор оставшихся лимитов.
- Для текущих квот SQLite выбирает только последние подходящие снимки. История остается доступна по запросу аналитики и прогноза.
- Команда "Справка" в меню окна и значка рядом с часами открывает встроенное руководство. В окне виджета справка также доступна по F1.
- Стрелка Antigravity раскрывает полученные от клиента группы или модели, остатки квот и известные сроки сброса. Раскрытие доступно независимо от таймеров диалогов других агентов.
- `Подробно по лимитам` открывает встроенное окно всех квот провайдеров и моделей.
- `Детальная аналитика` открывает встроенный AI Usage: токены, стоимость, треды, проекты, модели и timeline.
- Текущие квоты Claude в детальной аналитике и компактном виджете берутся из одного штатного выбора локального снимка. Для оценки недельного расхода за период используется штатная история Claude или последовательность снимков из базы от одного источника. Текущее значение другого источника в расчет не добавляется.
- GUI: Qt / PySide6. Tkinter и pystray не используются.

В разделе "Платежи по подпискам" окна "Все настройки…" пользователь указывает число и месяц последней оплаты (ДД.ММ) и сумму с валютой отдельно для каждого сервиса. Под названием сервиса показан ближайший ежемесячный платеж строго после сегодняшней локальной даты, например `04.12 · 20 $` после оплаты 04.11. Подсказка показывает дату с годом и полную сумму. Для 29, 30 и 31 числа в коротком месяце берется последний день, а в следующих месяцах снова используется исходное число. Открытый виджет пересчитывает срок при смене даты. Полная исходная дата хранится в прежней локальной настройке `monitor_subscription_payments` в `usage.db`. Чтобы убрать строку, нужно очистить оба поля и сохранить.

## Данные

- В Windows данные лежат в %LOCALAPPDATA%/ClaudeUsageManager, в macOS в ~/Library/Application Support/ClaudeUsageManager. Абсолютный путь AI_LIMITS_DATA_DIR задает другое расположение.
- usage.db хранит историю. connections.json хранит выбранные программы, каталоги и состояние подключений. app.log содержит диагностику.
- Исходные журналы AI-клиентов читаются только read-only.
- SQLite работает в WAL-режиме; `usage.db-wal` и `usage.db-shm` являются runtime-файлами и не считаются мусором.

## Лимиты

- Claude без HTTP-запросов к Anthropic читает официальный Claude Code Mod, штатный statusLine и локальную историю Claude Desktop. Выбирается самый новый допустимый снимок целиком, без смешивания аккаунтов или добавления сроков сброса из другого снимка; при равном времени предпочтителен Mod. Desktop хранит fh/sd, но не точные сроки сброса: после 30 минут снимок считается устаревшим, после 2 часов не используется. Время измерения отображается в подсказке состояния. 0% расхода допустим. Учетные данные и сетевые ответы не читаются.
- Подключение строки состояния выполняется по явному действию в настройках. Существующая сторонняя команда сохраняется. Для пользовательского каталога Claude учитывается снимок выбранного профиля.
- Codex получает текущую квоту и кредиты сброса через штатный локальный app-server (при сбое запрос повторяется один раз в том же цикле). CodexBar в runtime не используется. Штатный источник Codex и исторические записи старого адаптера учитываются в истории и кэше; GUI показывает «онлайн» только при совпадении источника фонового сервиса с сохранённым актуальным снимком. Grok берёт недельный лимит у собственного Grok CLI (см. ниже), запасной путь - локальный журнал Grok Build; токены и cookie виджет не читает и сам в сеть не ходит.
- Antigravity получает проценты и сроки сброса от своей команды agy --print /usage либо через официальный statusLine. Пользователь может задать пути в настройках. Для выбранного нестандартного профиля используется его собственная строка состояния.
- Короткий сбой источника не меняет цвет точки у Codex и Grok: последние живые данные остаются «онлайн» ещё 15 минут (`LIVE_FAILURE_GRACE`, подсказка точки называет время данных, причина сбоя не передается в API), причина сбоя пишется в `backend.log` один раз за серию. Если источник не отвечает дольше, показывается кэш (жёлтая точка). Claude и Antigravity этим правилом не затронуты. При временной недоступности источника интерфейс использует последний валидный кеш и явно показывает cached-state. Исторические записи CodexBar сохраняются только для обратной совместимости, executable CodexBar не запускается ни для одного поставщика; действующим провайдером Grok является официальный локальный Grok Build.
- Кредиты ручного сброса хранятся как отдельная модель `manual_resets` и никогда не преобразуются в quota window или автоматический `resets_at` окна.
- У Claude нет документированного API количества бонусных Reset for free и сроков их действия. Старые web/Desktop organization-usage, sessionKey, OAuth-провайдер и сетевой CodexBar опрос Claude удалены.
- Опционально пользователь вручную заносит каждый доступный бонусный сброс из Claude Settings > Usage через tray; данные хранятся в SQLite settings отдельным ключом, истёкшие предложения фильтруются при чтении. Redeem автоматически отслеживать нельзя, использованные сбросы надо удалять вручную. source=manual:claude-settings-usage и freshness=manual обязательны, никаких ложных live; unknown не приравнивается к 0. Исходный суффикс /N, индивидуальные сроки и подсказки остаются.
- Исторический codexbar:claude сохраняется для ретроспективных отчётов, но cached_snapshot никогда не показывает его как текущий аккаунт. После смены аккаунта состояние неизвестно до первой штатной передачи. Старый sessionKey не используется и не удаляется автоматически. Codex получает credits через локальный codex app-server.
- Grok provider (модуль `grok_provider.py`) получает данные от Grok CLI и из локального журнала. Выбирается самое новое полное корректное наблюдение; ответ с действующим недельным периодом без процента не считается успешным и повторяется через 20 секунд; неподходящий тариф или период повторяется не чаще чем через 150 секунд. Корректный ответ CLI повторно используется до 150 секунд с исходным временем наблюдения, а более свежая запись журнала может заменить его раньше. Записи старше 20 минут помечаются устаревшими. Последнее время наблюдения сохраняется в деталях окна; у старых записей без него время неизвестно. Формат источника и история совместимы с прежним `grok:local-billing-log`.
- Для Grok Build отображается единый недельный пул. История локальных сессий поступает из `~/.grok/sessions/**/summary.json`, без чтения переписок, секретов и домысливания токенов или стоимости. Прежний Cursor quota provider сохранён в репозитории как неиспользуемая историческая реализация и не вызывается текущим монитором.
- Суффикс /N добавляется к основному проценту в заголовке Claude и Codex, когда известен положительный `manual_resets.available_count`. Grok показывает недельный общий лимит. Antigravity показывает 5-часовую и недельную квоты одной группы, если они доступны. В автоматическом режиме выбирается группа с минимальным недельным остатком, а если недельных квот нет, с минимальным 5-часовым остатком. В настройках можно закрепить группу. Название группы видно в подсказке, все группы доступны по стрелке.

- Интерфейс ручных Claude Reset for free использует ограниченное по ширине диалоговое окно с `QDateTimeEdit`, кнопками добавления/изменения/удаления, явной надписью о ручном происхождении и корректными переносами строк. Состояние интеграции проверяется из трея локально, без HTTP к Anthropic. Отсутствие первого события `statusLine` обозначает ожидание данных, а не ошибку авторизации.

## Кэш тредов

- По умолчанию видны карточки агентов. У Claude Code, Codex и Grok Build кнопка со стрелкой раскрывает и сворачивает список диалогов. Состояние хранится в monitor_cache_expanded. У треда: короткое название, вторая строка "проект · среда" и кольцо с остатком времени. Дуга кольца пропорциональна доле оставшегося срока, цвет идет от зеленого (60% срока и больше) к красному; остывший тред - пустое кольцо и серое "остыл".
- Порядок внутри агента: сверху тред с наименьшей долей остатка, недавно остывшие внизу. В развернутом списке первые 3 треда (`COLLAPSED_THREADS`), остальные скрыты за кнопкой "Показать еще N"; компактный вид (`ThreadView.compact`, по умолчанию включен) - строка треда в две строки: кольцо `COMPACT_RING_SIZE` 36 с линией 3 и временем 5 пт обычной жирности (`COMPACT_RING_FONT`, `bold=False`); состояние треда - внутри кольца над временем (`CacheRing.set_activity`): индикатор диаметром `RING_STATE_SIZE` 6 на `RING_STATE_ABOVE` 6 выше центра, время на `RING_STATE_SHIFT` 3 ниже; работает - бегущий кружок по общему `SpinnerClock`, ждет ответа и не просмотрен - оранжевая и синяя точка; `StateDot` скрыт и не анимируется, текст встает вплотную к кольцу, поля 10/6, высота не меньше `COMPACT_ROW_HEIGHT` 44; первая строка - точка и название, вторая - проект (без среды, сокращается многоточием) и короткие чипы (`~N%` без "нед", доллары, монета с ценой перезаписи без слова, `glutton_mini` - значок пламени вместо строки "прожорливый"); среда и пояснения в подсказках; кнопки "Показать еще N" и "Свернуть список" переключают длину списка. Остывший тред остается в списке 10 минут. Кнопка раскрытия есть у Claude Code, Codex и Grok Build. У Antigravity отображаются квоты. Окно растет вверх и влево: правый нижний угол остается на месте (мини-виджет стоит в правом нижнем углу экрана), у края экрана рост упирается в край рабочей области; при сворачивании окно уменьшается к тому же углу.
- Оформление строки треда (`cache_threads_qt.py`, стили `STYLE` в `quota_monitor.py`): название крупнее и жирнее, проект второй строкой голубовато-серым, среда (Desktop, CLI, VS Code) отдельной плашкой справа от проекта, между строками тонкий разделитель, строка под курсором подсвечивается; высота строки-карточки 56 пикселей (кольцо 46, точка состояния рядом с названием). Строки лежат в прокручиваемой области внутри блока агента: окно не выше рабочей области экрана (запас 24 пикселя), лишнее уходит в прокрутку (`CacheThreadsBlock.set_height_cap`, `distribute_height_caps` урезает блоки поровну, но не ниже трех строк); кнопки "Показать еще N" и "Свернуть список" остаются под областью прокрутки.
- Вид списка и закрепление (CLA-6, этап 1; `thread_view.py`, `toggle_switch.py`, `MonitorWindow._make_drawer`): глобальные переключатели `ThreadView` (`timer`, `title`, `project` - проект и среда вместе, `warning` - предупреждение перед остыванием, `pin_hide`) хранятся JSON в настройке `monitor_thread_view` (по умолчанию все включено; значение не того типа или испорченное заменяется умолчанием). Шестеренка в заголовке окна открывает выезжающую панель "Вид тредов" с переключателями-таблетками и ссылкой "Все настройки…" (прежнее окно настроек); переключатель пересобирает строки сразу. В строках виджета нет кнопок закрепления и скрытия. Сохраненные правила `thread_rules` базы `usage.db` по-прежнему учитываются: закрепленные идут первыми, скрытые убираются, кнопка "Вернуть скрытые (N)" возвращает скрытые треды этого агента. В коротком списке 3 строки. Выключенный `pin_hide` правила не применяет и не стирает. Строка с выключенной частью не создает ее в раскладке (нет кольца, названия, проекта или значков). Проект и среда идут одной строкой `ElidedLabel` "проект · среда" (плашки среды нет). Предупреждение (`WARN_SECONDS` = 120 с, цвет `WARN_COLOR`): когда до остывания осталось не больше порога и срок еще не вышел, под строкой "проект · среда" показывается колокольчик с текстом "Остынет через …. Нужно ли написать?", строка получает свойство `warn` (желтая тонировка фона). `refresh` и `update_thread` возвращают `True`, если раскладка строки изменилась; блок тогда шлет `content_changed`, а окно подгоняет высоту (`_fit_to_content` определяет ширину, затем высоту всего содержимого при этой ширине; при разворачивании списка подгонка еще раз идет через `FIT_SETTLE_MS`).
- Карточка агента (`AgentCard`, `CompactRow`, `agent_summary` в `quota_monitor.py`): заголовок - имя агента (`AGENT_NAMES`) и текст остатков по ячейкам строки (`5 ч`, `нед`, короткие подписи известных групп Antigravity; кредиты ручного сброса суффиксом `/N` у основной ячейки), подсказка - остаток и срок сброса каждой ячейки и кредиты; точка состояния данных прежняя. В рамке `QuotaColumns` у каждого лимита свой столбец сетки Qt. Сверху показаны период и остаток, ниже отдельной меткой время до сброса (8 пт плюс сдвиг шрифта). При неизвестном или прошедшем сроке метка скрыта. Название и платеж расположены слева, точка источника рядом с названием. Предупреждение о полном сбросе занимает всю ширину следующей строки, прогноз и треды располагаются ниже заголовка. `MonitorWindow._update_clock` каждую секунду вызывает `_refresh_countdowns`: `CompactRow.refresh_countdown` меняет текст только при смене минуты без пересборки карточки и возвращает True при любой смене текста (меняется высота, если строка срока появилась или пропала, или ширина, например «1д 0ч» -> «23ч 59м»); тогда окно подгоняется (`_fit_to_content`) сразу и еще раз через `FIT_SETTLE_MS`, как в `_render`: вложенные раскладки отдают новый размер заголовка не сразу. Карточка развернутого агента: заголовок, `ForecastBar`, `CacheThreadsBlock`; разделители - свойство `divider`. Значок провайдера и сетка процентов удалены. Ширина развернутого окна без выбранной владельцем ширины - `DEFAULT_LIST_WIDTH` = 380.
- Расход тредов (`thread_usage.py`, `UsageScanner`, фоновый `UsageScanWorker` раз в 30 с при развернутом списке): Claude - строки `assistant` с `message.usage` из `~/.claude/projects/*/<id>.jsonl` и `<id>/subagents/*.jsonl` (субагенты относятся к треду; повтор одного `message.id` - последний кусок; `<synthetic>` и ошибки API не считаются); Codex - `token_usage_record` (ключ `response_id`, модель из последнего `turn_context`, тред - `session_id`). Файлы дочитываются с места остановки, неполная строка ждет следующего прохода; читаются только события с начала недели минус сутки. Неделя агента - сброс недельного окна (10080 минут) минус 7 суток; доля недели треда = недельный процент x стоимость треда / стоимость всех тредов агента за неделю (оценка). Перезапись: Claude - контекст последнего ответа основного треда (вход + запись + чтение кэша) по цене записи того яруса, в который кэш писался (1 час или 5 минут); Codex - вход последнего ответа по цене записи кэша на 30 минут, а если OpenAI ее не продает - по цене входа. «Прожорливый» - тред с наибольшей долей, только если долей хотя бы две.
- Цены (`pricing.py`): таблицы из https://platform.claude.com/docs/en/about-claude/pricing и https://developers.openai.com/api/docs/pricing (Standard) на 12.11.2026, доллары за миллион токенов; Haiku 5.5 - дорогой ярус запросов длиннее 100 тысяч токенов, OpenAI - цены длинного контекста свыше 272 тысяч. Модель без строки в таблице цены не получает (`None`, в окне «нет цены» или знак `+` у частично оцененной суммы).

## Локальный API

- Ранее настроенный отдельный сервер --backend остается доступным для локальных интеграций. Сетевой интерфейс привязан к 127.0.0.1. Для вновь установленного виджета отдельный процесс и прослушивание порта не требуются.
- `GET /health`, `GET /v1/snapshot`, `POST /v1/refresh` имеют стабильный JSON-контракт версии 1.
- Снимок содержит всех провайдеров, quota windows и отдельный `manual_resets` с `state`, `available_count`, отсортированными `items`, сроками, оставшимися секундами, источником и свежестью.
- Токены, cookies, account identifiers, исходные ответы провайдеров и внутренние ошибки в API не возвращаются. Для Codex и Grok в провайдере есть булев признак `degraded`: источник временно не отвечает, но последние живые данные (не старше 15 минут) еще показываются как `live`; причина сбоя пишется только в `backend.log`.
- Окно обновляет представление каждые пять секунд. Кнопка обновления запрашивает новый сбор. Пока данные отсутствуют, виджет показывает состояние соответствующего источника.
- Источники собираются независимо: Claude проверяется раз в 5 секунд, Grok раз в 10 секунд, остальные по выбранному интервалу. Настройка интервала не увеличивает эти сроки, но может сокращать их. Медленный поставщик не задерживает публикацию остальных. Claude читается только из локальных источников, без сетевых запросов; их собственную частоту обновления приложение изменить не может.

## Установка

## Acceptance gate

Перед публикацией изменений обязательно:

1. `python -m pytest -q` — весь набор тестов проходит, код выхода процесса 0. Тесты пишут журнал приложения в отдельный временный каталог сеанса pytest, живой `%LOCALAPPDATA%\ClaudeUsageManager\app.log` не трогают; окна Qt, оставленные тестом, удаляются после него (`tests/conftest.py`).
2. `git diff --check` — без ошибок.
3. PowerShell installer/packaging scripts парсятся без ошибок.
4. Windows runtime запускается из `monitor.py`.
5. Компактный виджет не даёт белых/светлых вспышек при refresh.
6. Desktop/Startup не содержат старых `Claude Usage Manager` shortcut.
